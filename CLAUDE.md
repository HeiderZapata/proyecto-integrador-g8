## What this is

Academic capstone (Proyecto Integrador G8, Maestría en Ciencia de Datos, EAFIT). It is **not an application** — there is no build, lint, or test suite. The deliverables are Jupyter notebooks, a Power BI dashboard, and documents. The project optimizes e-commerce conversion via a **purchase-propensity classifier + visitor clustering** over the REES46 clickstream dataset (Oct–Nov 2019, ~14.5 GB raw). The working language is **Spanish** — write code comments, commit messages, and docs in Spanish to match.

`docs/00_estado_del_proyecto.md` is the **master, living source of truth**: project state, decisions, the §-numbered sections that README/CONTRIBUTING cross-reference. Read it first to get oriented; keep it current when state changes.

## Two execution environments (this is the key architectural split)

The pipeline runs on the cloud; modeling runs locally on a frozen extract. Do not confuse the two.

1. **Databricks Free Edition (serverless)** — runs `notebooks/pipeline/` (ingesta + Medallion Bronze/Silver/Gold) and the cloud-only modeling steps (`01_extraccion_gold_a_parquet`, `06_scoring_mlflow_databricks`). Reads/writes Delta tables and Volumes under `/Volumes/workspace/default/...` (e.g. Gold at `.../e_commerce/gold/features_session`). **Notebooks here cannot be run from this repo** — they execute inside a Databricks Git folder. Running a notebook in Databricks does **not** push to GitHub; commits are manual (see CONTRIBUTING.md).
2. **Local (this machine)** — runs `notebooks/modeling/02_modelado_propension.ipynb` (propensity) and `04_clustering.ipynb` against the **frozen Gold snapshot** in `data/gold_snapshot/` (11 zstd Parquet parts, ~824 MB, ~22.99M sessions × 22 cols). This snapshot is **gitignored**; it is produced by running `01_extraccion_gold_a_parquet.ipynb` on Databricks (Delta → Parquet) and downloading it. `data/propension_model.joblib` is the trained local model artifact (also gitignored).

The data flows one way: **Databricks Gold (Delta) → Parquet snapshot → local modeling → model + Contrato 2 scored back in Databricks (MLflow + batch Delta).**

## Modeling conventions (non-negotiable — set in docs/00 §17–§18)

These are deliberate methodology decisions; preserve them in any modeling work:

- **Metric is PR-AUC + Brier, never accuracy** (severe class imbalance, base rate ~0.06).
- **Cuarentena: exclude the corrupt label window 14–17 Nov** (`label_window_corrupt == 1`) from **both** train and test.
- **Split = "Opción C"** (out-of-time): train = Oct + Nov ≤ 2019-11-23, test = 2019-11-24 to 2019-11-30. `StratifiedKFold` only for inner CV, never across the temporal frontier.
- **`is_black_friday`** is used only to stratify evaluation (report test with/without BF), **never as a feature**.
- **Imbalance handling** (`class_weight` / SMOTE) goes **inside the CV fold**, never before the split.
- **Feature engineering lives inside the sklearn pipeline** — do not mutate the frozen Gold.
- Operating threshold is set by cost/F1 (e.g. F1-optimal ≈ 0.092), **not** 0.5.
- Feature importance via **permutation importance** (built-in LightGBM split-count importance underestimates low-cardinality features — contrast both if reporting).

## Git workflow (one branch per frente, not per person)

Strict, because the team are Git novices. Full detail in `CONTRIBUTING.md`.

- **Never commit to `main`.** Work on your frente branch (`feat/modelo`, `feat/pipeline`, `feat/viz`, `feat/ab-test`, `feat/doc`); merge to `main` happens **only via PR, merged by Yeison** (backup Heider).
- Commit message format: `frente: qué hiciste` (Spanish, e.g. `modelo: baseline logístico con PR-AUC`).
- Each frente owns its folder: `modeling/` (Sara), `pipeline/`+`exploration/` (Heider/Yeison), `analysis/`+`reports/powerbi/` (Kelly). Touching another's folder → coordinate first.
- **Binary files** (`.pbix`, `.png`, `.docx`, `.xlsx`) cannot be merged — single editor at a time.
- Before pushing: `git pull origin main`, resolve conflicts in your branch so the PR is green.

## Data & secrets — what never goes in the repo

- Raw CSVs and large Parquet are **gitignored** (`/data/`, `*.csv`, `*.parquet`). The repo is code + docs, not a data lake.
- **Exception:** the small aggregated-Gold CSVs in `reports/data/` (≤ hundreds of rows, feed Power BI) **are** force-versioned (`!reports/data/*.csv`). They are regenerated by `notebooks/pipeline/03_gold_agregada_bi_*.ipynb` on the clean base and must match the EDA numbers.
- **Credentials never in code.** Kaggle ingestion reads `kaggle.json` from a Databricks Volume at runtime; `.gitignore` blocks `kaggle.json`. A leaked secret must be rotated at its service, not just deleted from a file.

## Databricks Free Edition gotchas

- Serverless only, with a fair-use quota: exceeding it **kills compute for the rest of the day**. Don't run heavy 14 GB jobs the night before a deadline; develop on a sample, run full only to validate.
- Streaming: only `Trigger.AvailableNow()` is supported (no continuous/interval triggers). Ingestion uses Auto Loader (`cloudFiles`) + `Trigger.AvailableNow` + checkpoint — a Kappa-style replay of the historical CSVs.
- **MLflow setup gotcha:** before `mlflow.set_experiment(...)`, call `mlflow.set_tracking_uri("databricks")` and `mlflow.set_registry_uri("databricks-uc")`, or it fails with `CONFIG_NOT_AVAILABLE: spark.mlflow.modelRegistryUri`. (doc 02 §4)
- Partitioning by layer: Bronze/Silver by date (Silver `ZORDER` by `category_id`); the **Gold session table is not partitioned** (~1.33 GB ≪ 1 TB → `OPTIMIZE` + `ZORDER (session_date, user_id)`). Never partition by high-cardinality columns.
